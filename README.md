# DiscVault

Каталог коллекционных изданий видеоигр: абстрактный каталог игр, конкретные
издания, личная коллекция физических экземпляров и маркет объявлений/аукционов.
Проект — React-переписывание однофайлового прототипа с сохранением визуального
языка и сборкой в **один HTML-файл**.

Модель данных: **`Game` → `Edition` → `Copy` / `MarketEntry`**.

- `Game` — абстрактная игра: название, издатель, разработчик, серия, год, жанры,
  описание и обложка. Без платформы, региона, языка и комплектности.
- `Edition` — конкретное издание: платформа, регион, язык, носитель, дата
  выхода, комплектация, описание и собственные обложки. DNS `data-product`
  хранится как `dnsProductId` и однозначно привязывает издание к карточке товара.
- `Copy` — физический экземпляр пользователя, всегда ссылается на издание.
- `MarketEntry` — объявление или аукцион игры либо отдельного лута. Для игры
  издание обязательно при продаже, обмене и аукционе; для «Куплю» и для лута
  допускается `editionId: null`.

## Стек

- React 19.3 + TypeScript 7.0 (строгий режим, без `any`)
- Vite 8 + `vite-plugin-singlefile`
- `react-router-dom` 7 — `HashRouter`, чтобы собранный файл работал с `file://`
- `lucide-react` вместо CDN-скрипта Lucide
- Данные приложения — Fastify API и PostgreSQL: каталог, коллекция,
  маркет, профили, оценки пользователей, обсуждения и новости.
- JSON в `src/data` используется для начального наполнения БД и справочников;
  frontend не подставляет демонстрационные записи при ошибке сервера.

## Команды

```bash
npm install       # зависимости
npm run dev       # dev-сервер
npm run typecheck # проверка типов
npm run build     # typecheck + сборка в dist/index.html и discvault_stage3.html
npm run preview   # предпросмотр production-сборки
```

Готовый файл: **`dist/index.html`**. `postbuild` дополнительно кладёт копию в
`discvault_stage3.html` в корне. Оба файла генерируются сборкой и не коммитятся.
CSS и JS встроены внутрь. Для работы приложения нужен доступный API: при
отсутствии сервера отображается ошибка с повторной загрузкой. Данные коллекции,
объявления и оценки сохраняются на сервере после входа в аккаунт.

## Публикация тестового стенда

Для полноценной проверки с API, PostgreSQL и HTTPS подготовлен Docker Compose
стенд: Caddy раздаёт `dist/index.html` и проксирует `/api/*` и `/uploads/*` на
Fastify, PostgreSQL и загрузки хранятся в volumes. Инструкция по VPS:
[`deploy/README.md`](deploy/README.md).

Коротко на сервере с Docker:

```bash
cp deploy/env.production.example .env
# заполнить APP_DOMAIN, пароли и SEED_DEMO_*
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml exec api npx prisma db seed
```

## Каталог и игра

Каталог загружается порциями по 24 игры. Следующая порция запрашивается при
приближении к концу списка; есть также кнопка «Загрузить ещё». Поиск и фильтры
применяются в API до пагинации, ввод поиска обрабатывается с задержкой 300 мс.
Смена фильтров или аккаунта отменяет старый запрос и начинает список заново.
Ошибка следующей порции сохраняет уже показанные карточки и позволяет повторить
запрос той же страницы. Показан общий результат поиска, а не только число
загруженных карточек.

При открытии `#/games` глобальное хранилище не скачивает полный каталог игр и
изданий. Обложки, платформы, отметка коллекции и счётчики маркета входят в
ответ страницы; справочники фильтров загружаются отдельным компактным запросом.
Полные издания и маркет конкретной игры запрашиваются при открытии карточки,
включая переход по прямой ссылке на игру вне уже загруженных страниц.

Администратор видит кнопку «Добавить игру» в панели поиска каталога и кнопку
«Редактировать игру» в открытой карточке. Обе открывают общий редактор записей
`Game` через защищённый административный API. После создания открывается
карточка новой игры; после сохранения обновляются каталог и карточка с
сохранением выбранных фильтров. У гостей, пользователей и модераторов эти
кнопки отсутствуют; сервер также проверяет роль `admin` на каждом изменении.

- Одна карточка каталога = одна игра, а не отдельная платформа или издание.
  Карточка показывает платформы, число изданий, число лотов и отметку «На полке».
- Панель поиска и фильтров — общий `SearchToolbar`. В каталоге доступны `q`,
  `platform`, `lang`, `year`, `region`, `edition`. Комплектность осталась только
  в маркете: она относится к конкретному экземпляру, а не к абстрактной игре.
- Фильтры каталога применяются через издания: игра проходит, если хотя бы одно
  её издание совпадает по платформе, региону, языку или названию издания.
- Карточка игры живёт в URL: `#/games?game=elden-ring` открывает drawer сразу.
  `editionId` выбирает конкретное издание: `#/games?game=elden-ring&editionId=...`.
- В drawer: описание игры, спецификация и блок «Издания», сгруппированный по
  платформам. У каждого издания своя обложка, регион, язык, дата, комплектация и
  кнопки «В коллекцию» и «Объявления».
- Выбранное издание фильтрует вкладки маркета игры и подставляется в форму
  размещения. Вкладки: «Лоты», «Продажи и Покупки», «Обмен», «Обсуждения».
- «Разместить объявление» и «Разместить аукцион» передают игру и выбранное
  издание: `#/listings/sales?compose=1&game=...&editionId=...` или
  `#/auctions?compose=1&game=...&editionId=...`.

## Коллекция

- Коллекция хранит `Copy`, но визуально группируется по изданию: одна карточка
  на издание, а количество экземпляров показывается бейджем и степпером.
- Повторное добавление того же издания увеличивает количество, а не создаёт
  вторую карточку. Количество меняется кнопками `−`/`+` от 1 до 99.
- Кнопка редактирования на карточке открывает состояние, комплектность, цену и
  дату покупки, заметки и фотографии. Эти поля общие для всех экземпляров одного
  издания; при количестве больше одного форма предупреждает, что изменения
  применятся ко всей группе.
- Цена покупки хранится в рублях как необязательное целое число, дата — как
  `YYYY-MM-DD`. Если они не указаны, карточка просто не показывает строку
  покупки.
- Новые экземпляры при `+` наследуют состояние, комплектность, цену и дату
  покупки, а также заметки существующей группы. Фото хранятся только на
  репрезентативной записи, чтобы не дублировать крупные data URL при увеличении
  количества.
- Репрезентативная запись — самая ранняя по `createdAt`; карточки сортируются по
  времени последнего добавления.
- Карточку можно открыть в каталоге вместе с её изданием или убрать издание
  целиком с полки.
- Старые сохранения `discvault_owned` мигрируют в `discvault_copies`: каждая
  owned-игра становится экземпляром первого издания этой игры.

## Маркет

- В форме «Что размещаете» выбирается предмет: игра/издание, обложка, мануал,
  карта, саундтрек, фигурка, стилбук или другой лут. Любой предмет можно продавать,
  искать для покупки, обменивать и выставлять на аукцион.
- Лут всегда связан с игрой; издание необязательно. На карточке и в деталях
  отображается категория. Фильтр «Предмет» и поиск помогают найти нужный лут.
- Старые записи без `itemType` читаются как `game`. Для API добавлена миграция
  `20261025150000_market_loot`; после первой ставки менять категорию нельзя.
- Проверка правил и совместимости: `node --import tsx --test scripts/market-items.test.ts`.

- Платформа, регион, язык и название издания берутся из `Edition`, а не из
  записи маркета. Для «Куплю» издание может быть не указано — тогда карточка
  показывает «Любое издание».
- В форме размещения сначала выбирается игра, затем конкретное издание.
  Продажа, обмен и аукцион требуют издание; для покупки доступен вариант
  «Любое издание».
- У объявления есть тип: «Продажа», «Покупка» или «Обмен». Тип показывается
  бейджем на плитке и в карточке и меняет подпись цены.
- В левом меню объявления разделены на «Продажи», «Покупки» и «Обмен».
  Общая лента `#/listings` сохранена для старых ссылок и мобильной вкладки.
- В форму можно приложить до шести фотографий. Браузер уменьшает длинную
  сторону до 1200 px и перекодирует в JPEG; фото хранятся как data URL.
- Форма собирает службы доставки, отправку за границу, цену упаковки и город
  отправки. Для аукциона дополнительно задаются шаг цены и даты открытия и
  закрытия.
- Пользовательские записи лежат в `discvault_market` и добавляются к
  демо-записям из `market.json`; демо-файл не перезаписывается.
- У локальной записи есть статус: `active`, `sold` или `closed`. В общей ленте
  видны только активные записи; проданные и снятые доступны через кнопку
  «Мои».
- Кнопка «Мои» показывает только записи этого устройства и оформлена как
  иконка того же размера, что и фильтры. Подсказка зависит от раздела: «Мои
  объявления» в объявлениях и «Мои лоты» на аукционах. Свою запись можно
  отредактировать, отметить проданной, снять с продажи, вернуть в продажу или
  удалить с подтверждением.
- Кнопка размещения и иконка «Мои» встроены в общую панель поиска, причём
  «Мои» стоит перед кнопками фильтров. На узких экранах панель перестраивается
  в колонку и не создаёт горизонтальную прокрутку.
- Редактирование переиспользует форму размещения и сохраняет автора, дату
  создания, ставки и текущий статус.
- Сайт работает как доска объявлений: оплата и доставка обсуждаются напрямую
  между продавцом и покупателем. API фиксирует лот, ставку и факт сделки для
  истории и отзывов, но не проводит платежи.

## Жалобы

- Жаловаться на лот или публичный профиль может только авторизованный
  пользователь; жалоба на себя и повторная открытая жалоба на ту же цель
  отклоняются.
- На лоте и в публичном профиле есть форма с причиной и необязательным
  комментарием. Жалобы хранятся в PostgreSQL, а не в `localStorage`.
- Раздел «Жалобы» — тот же React-клиент по адресу `#/admin/reports`; ссылка
  в навигации появляется только у роли `admin` или `moderator`.
- Модератор может взять жалобу в работу, скрыть объявление или отклонить
  обращение. Блокировать пользователя может только `admin`; при блокировке
  удаляются его сессии, а публичные лоты и профиль перестают отдаваться API.
- Скрытые лоты остаются у владельца во вкладке «Мои» с пометкой модерации.
  Демо-аккаунт можно сделать администратором через `SEED_DEMO_ROLE=admin`.

## Модерация лотов перед публикацией

- Новые объявления и аукционы создаются в статусе `pending` и не попадают в
  общую ленту, публичную детальную страницу, ставки и сделки до одобрения.
- Раздел «Модерация» находится по адресу `#/admin/market` в блоке
  «Администрирование». Модератор или администратор может одобрить лот,
  отклонить его и оставить комментарий для автора.
- API очереди: `GET /api/v1/admin/market?status=pending`; решение принимается
  через `PATCH /api/v1/admin/market/:id/moderation` со статусом `visible` или
  `hidden`.
- При одобрении подписчики игры получают обычное уведомление о новом лоте, а
  автор — уведомление о результате проверки. При отклонении автор видит причину
  в уведомлении, а лот остаётся в его разделе «Мои» со статусом «Скрыто». До
  решения он отображается там как «На проверке».
- Пока лот на проверке, владелец может редактировать или удалить его, но не
  может открыть сделку, сделать ставку или отметить лот проданным.

## Административная аналитика

- Раздел `#/admin/analytics` сгруппирован в левом меню под блоком
  «Администрирование» и доступен ролям `admin` и `moderator`.
- Дашборд показывает KPI по пользователям, каталогу, активным лотам, лотам на
  проверке, сделкам, ставкам и очереди жалоб, а также динамику регистраций,
  новых лотов и завершённых сделок за выбранный период. Активные лоты считаются
  только по опубликованным записям.
- Отдельные таблицы дают срез по играм (издания, копии, лоты, сделки, GMV,
  рейтинг) и пользователям (топ продавцов, покупателей и коллекционеров,
  распределение ролей).
- Данные считает серверный эндпоинт `GET /api/v1/admin/analytics?period=30d`.
  В автономной сборке без API раздел показывает поясняющее состояние.

## Пользователи

Администратор может создавать, редактировать и удалять аккаунты в `#/admin/users`.
Столбец ID показывает полный идентификатор пользователя, поддерживает фильтрацию
и сортировку. В разделе «Данные» кнопка «Пользователи» открывает отдельный
плоский список `#/admin/data/User` с ID и полями записи, без перенаправления
на страницу управления пользователями со статистикой.
В таблице управления пользователями есть индикатор «В сети» и дата/время
последнего посещения. Пользователь считается онлайн, если его действующая
сессия была активна за последние 2 минуты. Видимая вкладка отправляет heartbeat
раз в минуту, список пользователей обновляется раз в 30 секунд. История
посещения хранится в `User.lastSeenAt`, сохраняется после выхода и доступна
только для чтения. Для старых аккаунтов миграция
`20261027000000_user_presence` переносит последнее известное время из сессий;
без истории показывается «Нет данных».

Верхняя таблица ограничена по высоте, показывает по 10 записей на странице
и прокручивается внутри. Нажатие на строку (или Enter/пробел на ней) выбирает
пользователя. Под таблицей расположены плашки моделей с прямыми ссылками на
`User`. Активная плашка показывает в нижней таблице записи выбранного
пользователя. Если ссылок несколько (покупатель/продавец, автор/получатель
отзыва и т. п.), учитывается любая из них. Фильтр пользователя применяется
на сервере до пагинации и сохраняется при поиске и сбросе фильтров нижней
таблицы. Нижняя таблица и плоские списки раздела «Данные» используют общий
`AdminRecords`, `AdminDataTable` и редактор записей.
Поиск по имени/почте, фильтры всех прежних столбцов, сортировка и постраничный
вывод сохранены. Лоты, сделки, коллекция и рейтинг вычисляются по связанным
записям; изменить их непосредственно в форме пользователя нельзя. Пароль
задаётся при создании, при редактировании пустое поле сохраняет прежний пароль.
Пароли хешируются Argon2id, хеши не передаются клиенту. Изменение пароля, роли,
статуса или признака демо-аккаунта отзывает сессии пользователя.

Раздел **«Данные»** (`#/admin/data`) даёт администратору страницы всех 19 моделей
из Prisma-схемы: игры, издания, коллекции и фотографии, маркет и фотографии,
ставки, сделки, отзывы, оценки, жалобы, уведомления, подписки, обсуждения,
комментарии, новости, пользователи и сессии. Сессии доступны для просмотра и
отзыва; создание происходит при входе пользователя. Для остальных моделей
есть создание, редактирование и удаление. Идентификаторы при редактировании
не меняются; составной ключ оценок игр поддерживается. Суммы в формах базы
данных явно указаны в копейках.

Все страницы используют один `AdminDataTable` и один `AdminRecordDialog`.
Типы полей, варианты перечислений, обязательность и связи берутся из
метаданных allowlist моделей на сервере. Связанную запись можно найти по
тексту и выбрать из списка. Поиск и фильтры остальных таблиц выполняются
на сервере до пагинации; числовые значения ищутся точно, даты — за выбранный
день UTC, списки — по вхождению элемента. Служебные поля и агрегаты доступны
только для чтения; хеши паролей и токенов сессий исключены из метаданных и выдачи.

API `/api/v1/admin/data/*` проверяет роль `admin` для каждого запроса, строго
валидирует поля и выполняет изменения транзакционно. При наличии `updatedAt`
устаревшая форма получает `409` вместо перезаписи новых данных. Собственный
аккаунт администратора нельзя удалить, заблокировать или понизить в роли.
Удаление с зависимостями блокируется с перечнем связанных таблиц: сначала
переназначьте либо удалите эти записи, после чего повторите удаление.
Корректировка отзывов пересчитывает рейтинг, ставок — счётчик и текущую цену,
сделок — состояние лота; проверяются связи издания с игрой и участники сделки.

Проверки: `npm run test:admin`. HTTP-тесты работают без БД; интеграционная
проверка всех моделей запускается только с `CI=true` и изолированной
`DATABASE_URL`, содержащей `/discvault_ci`. Она включена в GitHub Actions.

- Раздел `#/admin/users` доступен только роли `admin` и показывает все
  зарегистрированные аккаунты в таблице: роль, статус, комментарий, число лотов,
  сделок и экземпляров в коллекции, рейтинг и дату регистрации.
- Список можно искать по имени или почте, фильтровать по роли, статусу,
  комментарию и другим столбцам, сортировать и листать страницами.
- Данные отдаёт `GET /api/v1/admin/users?search=&role=&status=&comment=&sortBy=&sortDir=&page=1&pageSize=20`.
  Эндпоинт и страница доступны только администратору; модераторы видят разделы
  «Модерация» и «Жалобы», но не список пользователей.

## Уведомления и подписки

- Уведомления доступны только в сетевом режиме с PostgreSQL: автономная
  single-file сборка показывает поясняющее пустое состояние, а кнопки подписки
  скрыты.
- Автор лота автоматически получает уведомления о новых ставках; предыдущий
  лидер — о перебитой ставке; участники аукциона — о победе или проигрыше.
- Подписка на игру (`GameSubscription`) присылает уведомления о новых лотах и
  объявлениях выбранной игры. Подписка на конкретный лот
  (`MarketEntrySubscription`) — о ставках, изменении цены, снятии, повторном
  открытии и закрытии.
- Наблюдатели получают уведомления о сделке, продаже и закрытии аукциона.
  Автор нового лота получает уведомление о результате проверки перед
  публикацией. Действующий пользователь не уведомляется о собственном действии.
- Непрочитанные уведомления доступны по адресу `#/notifications`; счётчик
  обновляется каждые 30 секунд и показывается в топбаре и сайдбаре.
- Повторные события отсекаются уникальным `dedupeKey`, а массовая вставка идёт
  через `createMany({ skipDuplicates: true })`.

## Совместимость со старой версией

- `styles.css` сохраняет исходный визуальный язык; стили карточек, модалки,
  изданий, экземпляров и адаптива живут в одном файле.
- Стартовые игры, издания, записи маркета и справочники вынесены в JSON-файлы
  `src/data`. Они встраиваются в single-file HTML, поэтому `file://` работает
  без запросов к серверу.
- Ключи `discvault_games`, `discvault_owned`, `discvault_market` и `theme`
  сохранены; добавлен `discvault_copies`.
- Старый `discvault_owned` (id игр) мигрирует в `Copy` по первому изданию игры.
- Старые маркет-записи с `edition` + `region` получают `editionId` через
  справочник изданий. Если издание не найдено, продажа/аукцион привязываются к
  первому изданию игры; «Куплю» может остаться без издания.
- `listingType` появился вместе с типами объявлений: старые записи без него
  читаются как «Продажа», у аукционов тип всегда `null`.
- `status` появился у маркета вместе с разделом «Мои»: старые записи и
  демо-данные без него читаются как `active`.
- `condition`, `completeness`, `purchasePrice`, `purchaseDate`, `notes` и `photos`
  у `Copy` редактируются; схема хранения не менялась, а фото группы хранятся на
  одной репрезентативной записи.
- `purchasePrice` и `purchaseDate` появились позже остальных полей `Copy`: у
  старых записей парсер подставляет `null` и пустую строку.
- `photos` и логистические поля (`deliveryServices`, `internationalShipping`,
  `packagingPrice`, `shipsFrom`) необязательны для старых записей: парсер
  подставляет пустой список, `null` и пустую строку.
- `startsAt` и `bidStep` у старых аукционов могут отсутствовать — открытие
  подставляется из `createdAt`, шаг цены показывается как «Не указан».

## Осознанные улучшения

- JSX вместо `innerHTML` — пользовательские строки не могут внедрить HTML.
- Безопасный парсинг `localStorage`: битые данные не ломают приложение.
- JSON-данные проходят через те же проверки, что и `localStorage`; обязательные
  поля проверяются типами при сборке, издания связываются с играми по `gameId`.
- Фотографии не загружаются на сервер: браузер уменьшает и пережимает их в JPEG.
- Фото группы одинаковых экземпляров хранятся один раз на репрезентативной
  записи, поэтому увеличение количества не раздувает `localStorage`.
- Цвета платформ хранятся в `platforms.json`, а не в CSS.
- Строгая типизация, чистые функции фильтрации и `React.memo` для карточек.
- Доступность: `role`/`aria`, открытие карточки с клавиатуры, фокус-трап в
  модалке, возврат фокуса, `aria-modal`, подписи у полей, `aria-current` у
  навигации, закрытие sheet по Escape.
- Тема применяется до первой отрисовки (без вспышки), цена валидируется (> 0).
- Открытая игра и выбранное издание попадают в URL, поэтому ссылкой можно
  поделиться, а «Назад» закрывает drawer.
- Кастомный `FilterDropdown` — ARIA-listbox с группами, галочкой и клавиатурой.

## Иконки

В старой версии Lucide заменял `<i data-lucide>` на `<svg>`, из-за чего часть
CSS-правил с селекторами `i` не срабатывала. В React-версии селекторы обновлены
на `svg`:

- переключатель темы показывает солнце в светлой теме и луну в тёмной;
- иконка поиска находится внутри поля ввода, а не в потоке над ним;
- иконка диска на обложке — 44 px (34 px на мобильных).

## Backend

Публичный профиль доступен по `#/users/:id`: имя, аватар, город, дата регистрации,
рейтинг, завершённые сделки, отзывы и активные объявления/аукционы. Переходы
доступны по имени автора объявления, темы, ответа, отзыва и участника сделки.
В аккаунте есть кнопка «Публичный профиль». Объявления и отзывы разбиты на страницы.
Email, телефон и личная коллекция в публичном профиле не отображаются.
В локальном режиме авторы встроенных демо-данных имеют демонстрационные профили
по `#/users/demo%3Aимя`; рейтинг и отзывы для них не выдумываются.

Fastify + PostgreSQL API: setup, Docker Compose, migrations, seed, endpoints and demo credentials are documented in [server/README.md](server/README.md).
