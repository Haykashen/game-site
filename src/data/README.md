# Данные каталога

Исходные данные лежат в JSON-файлах. Они импортируются на этапе сборки и
попадают внутрь single-file бандла: приложение не делает `fetch`, поэтому
собранный `index.html` по-прежнему работает через `file://`.

Пользовательские изменения — коллекция и записи маркета — хранятся отдельно в
`localStorage` и не перезаписывают эти файлы.

## Модель

**`Game` → `Edition` → `Copy` / `MarketEntry`**

- `games.json` — абстрактные игры.
- `editions.json` — конкретные издания: платформа, регион, язык, носитель,
  дата выхода, комплектация, описание и обложки.
- `market.json` — демо-объявления и аукционы, связанные с `gameId` и
  `editionId`.
- `Copy` не лежит в JSON: это пользовательский физический экземпляр в
  `localStorage`.

## Файлы

| Файл             | Что содержит                                           |
| ---------------- | ------------------------------------------------------ |
| `platforms.json` | платформы, их группы и цвета бейджей                    |
| `filters.json`   | языки, регионы, издания, комплектность, диапазоны годов |
| `games.json`     | абстрактные игры                                       |
| `editions.json`  | конкретные издания и их обложки                        |
| `market.json`    | демо-объявления и аукционы                             |
| `index.ts`       | валидация, группировка и сборка `Game[]`/`Edition[]`    |

## Форматы

### `platforms.json`

```json
{
  "name": "PS5",
  "group": "PlayStation",
  "color": "#2563eb",
  "textColor": "#ffffff"
}
```

`color` и `textColor` подставляются в бейдж платформы на карточке и в drawer.
Группы в фильтре строятся по полю `group` в порядке массива.

### `filters.json`

Справочники для фильтров и карточек: `languages`, `regions`, `editions`,
`completeness`, а также `yearRanges`.

`yearRanges[].max: null` означает открытый верхний диапазон («После 2010»).
При загрузке он превращается в `Number.POSITIVE_INFINITY`.

Значения `platform`, `lang`, `region` и `name` у изданий должны быть в
справочниках `platforms.json` / `filters.json` — иначе загрузчик бросит ошибку с
подсказкой.

### `games.json`

Поля игры: `id`, `title`, `publisher`, `developer`, `series`, `year`, `genres`,
`description`, `coverImage`.

`platform`, `lang`, `region`, `edition` и `completeness` здесь **не хранятся**:
это свойства конкретного издания. `coverImage` — необязательная обложка для
карточки; если она пустая, карточка использует обложку первого издания.

### `editions.json`

Поля издания: `id`, `gameId`, `name`, `platform`, `region`, `lang`, `media`,
`releaseDate`, `description`, `contents`, `coverImages`, `barcode`,
`dnsProductId`, `dnsProductCode`.

- `gameId` должен существовать в `games.json`.
- `name` — Standard, Launch Edition, Collector's Edition, Limited Edition.
- `platform` — значение из `platforms.json`.
- `region` и `lang` — значения из `filters.json`.
- `releaseDate` — `YYYY-MM-DD` или пустая строка.
- `contents` — список вложений: «Диск», «Мануал», «Артбук» и т. п.
- `coverImages` — до восьми URL (`https://…`) или data URL. Первое изображение
  становится обложкой карточки издания.
- `barcode` — свободный текст или пустая строка.
- `dnsProductId` — DNS `data-product` конкретной карточки товара. Это стабильный
  идентификатор издания во внешнем каталоге DNS; одно значение не может
  повторяться у разных изданий. Пустая строка — если товара в DNS нет.
- `dnsProductCode` — DNS `data-code` (артикул) для поиска и сверки.

### `market.json`

Демо-записи для разделов «Аукционы» и «Объявления». Поля: `id`, `kind`
(`listing` или `auction`), `listingType` (`sale`, `purchase`, `exchange` или
`null`), `gameId`, `editionId`, `title`, `condition`, `price`, `seller`,
`description`, `status`, `photos`, `deliveryServices`, `internationalShipping`,
`packagingPrice`, `shipsFrom`, `bids`, `bidStep`, `startsAt`, `endsAt`,
`createdAt`.

- `gameId` должен существовать в `games.json`.
- `editionId` должен существовать в `editions.json` и принадлежать той же игре.
- Для продажи, обмена и аукциона `editionId` обязателен. Для «Куплю» допускается
  `null` — это означает «любое издание».
- У объявления `listingType` обязателен: `sale` — продажа, `purchase` — покупка,
  `exchange` — обмен. У аукциона всегда `null`.
- Старые пользовательские объявления без `listingType` читаются как `sale`, а
  старые `edition` + `region` мигрируют в `editionId`.
- `seller` — автор лота. В форме поле не показывается: для локальных записей
  туда автоматически попадает текущий пользователь («Вы»).
- `status` — жизненный цикл: `active`, `sold` или `closed`. В демо-JSON поле
  можно не указывать: загрузчик подставляет `active`. Пользовательская запись
  создаётся активной, а владелец может отметить её проданной, снять с продажи или
  вернуть в продажу.
- У объявления `bids: 0`, `bidStep: null`, `startsAt: null` и `endsAt: null`.
- У аукциона `bids` — неотрицательное число ставок, `bidStep` — положительный
  целый шаг цены в рублях, `startsAt` и `endsAt` — ISO-дата и время открытия и
  закрытия. Дата закрытия должна быть позже даты открытия.
- `createdAt` — ISO-дата публикации.
- `photos` — массив до шести изображений в виде `data:image/...` URL. У демо-
  записей он обычно пустой. Пользовательские фото сжимаются в браузере и
  попадают в тот же массив при сохранении.
- `deliveryServices` — непустой массив без повторов из `russian-post`, `cdek`,
  `yandex`, `other`.
- `internationalShipping` — `true` или `false`.
- `packagingPrice` — неотрицательное целое число рублей. `0` значит
  «Бесплатно»; `null` — «Не указана».
- `shipsFrom` — город или регион отправки, непустая строка до 80 символов.
- Пользовательские записи добавляются в `localStorage` (`retrokeep_market`).
  Общая лента показывает только активные записи, а свои проданные и снятые —
  через переключатель «Мои».

### Коллекция

`Copy` хранится в `retrokeep_copies`:

```json
{
  "id": "…",
  "editionId": "elden-ring-ps5-launch-pal",
  "condition": "Не указано",
  "completeness": "Не указано",
  "notes": "",
  "photos": [],
  "createdAt": "2026-10-22T10:00:00.000Z"
}
```

Старый ключ `retrokeep_owned` (массив id игр) мигрирует в `Copy` по первому
изданию каждой игры.

Состояние, комплектность, заметки и фото редактируются из карточки коллекции.
Эти поля общие для группы с одним `editionId`; при количестве больше одного форма
предупреждает, что изменения применятся ко всем экземплярам. Новые `Copy` при
нажатии `+` наследуют состояние, комплектность и заметки группы, а фото хранятся
только на самой ранней записи, чтобы не дублировать крупные data URL.

Один `Copy` — один физический экземпляр. Коллекция группирует записи по
`editionId`: одинаковые издания показываются одной карточкой, а количество —
это число `Copy` с этим `editionId`. Кнопки `−`/`+` создают и удаляют отдельные
записи, поэтому схема хранения не меняется.

## Как добавить игру

1. Добавьте абстрактную игру в `games.json`.
2. Добавьте одно или несколько изданий в `editions.json` с тем же `gameId`.
3. Добавьте демо-записи в `market.json` с `gameId` и `editionId`.
4. Если используется новая платформа, добавьте её в `platforms.json`.
5. Если появился новый регион, издание или комплектность — добавьте значение в
   `filters.json`.
6. Запустите `npm run typecheck` — загрузчик проверит обязательные поля и связи.
